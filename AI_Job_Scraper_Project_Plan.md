# AI Job Scraper & Drafter: Project Plan

## 1. Project Overview
This project is an automated AI assistant designed to streamline the job search process. As per the MVP (Minimum Viable Product) requirements, the system will read job descriptions from a set of mocked/simple sources, evaluate them against a hardcoded CV, and automatically draft a personalized cover letter for the roles that are a good match. The output will be saved locally for manual review.

**Core Philosophy:** "Human in the Loop." The agent prepares the data and writes the drafts, but the human decides whether to actually apply.

---

## 2. Tech Stack & Architecture
* **Web Scraping / Extraction:** `Playwright` (using local HTML files for the MVP to avoid anti-bot blocking).
* **Agentic Orchestration:** `LangGraph` (to manage the state and control the flow of data between different AI tasks).
* **LLM & Reasoning:** `OpenAI API` (gpt-4o-mini or gpt-4o).
* **Structured Output:** `OpenAI Tool Calling` (to ensure the AI outputs strict JSON formats for match evaluations and data saving).
* **Environment:** Python 3.10+

---

## 3. The LangGraph State & Workflow

### 3.1 Defining the State
In LangGraph, you need a "State" dictionary that passes through each step. For this project, the state will look something like this:

    from typing import TypedDict

    class JobState(TypedDict):
        job_title: str
        company: str
        job_description: str
        my_cv: str
        is_match: bool          # Evaluated by Node 1
        match_reason: str       # Evaluated by Node 1
        cover_letter: str       # Generated by Node 2

### 3.2 The Nodes (Agents)
1. **Node 1: The Evaluator Agent**
   * **Input:** `job_description` and `my_cv`.
   * **Task:** Act as a strict technical recruiter. Compare the job requirements to the CV.
   * **Output:** Uses OpenAI Tool Calling to return a structured JSON response with `is_match` (True/False) and `match_reason` (a 1-2 sentence explanation).

2. **Conditional Router**
   * If `is_match == True` ➡️ Go to Node 2.
   * If `is_match == False` ➡️ End workflow for this job (skip drafting).

3. **Node 2: The Drafter Agent**
   * **Input:** `job_description`, `my_cv`, and `match_reason`.
   * **Task:** Write a highly professional, 3-paragraph cover letter highlighting the specific overlapping skills.
   * **Output:** Updates the `cover_letter` field in the state.

4. **Node 3: The Exporter**
   * **Task:** Takes the final state and saves it to a local Markdown or CSV file so you can review it later.

## 4. Step-by-Step Implementation Guide

### Phase 1: Setup and Mock Data (Days 1-2)
1. **Initialize the project:** Create a virtual environment and install dependencies (`pip install playwright langgraph langchain-openai python-dotenv`).
2. **Install Playwright browsers:** Run `playwright install`.
3. **Create mock data:** * Go to a job board (LinkedIn, Indeed) in your browser.
   * Find 2 jobs you like and 1 job you are totally unqualified for.
   * Right-click and "Save Page As" -> `job1.html`, `job2.html`, `job3.html` into a `mock_data/` folder.
4. **Write the Playwright Script:** Create a Python script to open these local `file://` paths, extract the title and text using basic selectors, and print them to the console.

### Phase 2: Building the Agents (Days 3-4)
1. **Set up OpenAI:** Add your `OPENAI_API_KEY` to a `.env` file.
2. **Build the Evaluator:** Write the prompt for the Evaluator agent and bind a tool (Pydantic schema) to force it to return a boolean and a reason. Test it manually with the extracted text.
3. **Build the Drafter:** Write the prompt for the Drafter agent. Test it manually to ensure the cover letter tone is professional and not overly "robotic".

### Phase 3: Wiring it up with LangGraph (Days 5-6)
1. **Define the Graph:** Initialize `StateGraph(JobState)`.
2. **Add Nodes:** Add the Evaluator and Drafter functions as nodes.
3. **Add Edges:** Create the conditional logic (`add_conditional_edges`) to only route to the Drafter if `is_match` is true.
4. **Compile:** Compile the graph and run one of your extracted mock jobs through the entire pipeline.

### Phase 4: Output & Polish (Day 7)
1. **Write to File:** Create a simple Python function that runs at the end of the graph to save successful matches into an `outputs/` directory (e.g., `job1_draft.md`).
2. **Review:** Run all 3 mock jobs through a loop. Verify that the system ignores the unqualified job and generates lovely drafts for the two good ones.

Once the MVP is working flawlessly locally, you can implement the "nice-to-haves" originally discussed:
